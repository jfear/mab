# 06 — The alignments plugin: pileup data model, coverage, modifications, layout

JBrowse 2 v4.3.0 (commit 83ac4507cf). Chapters 04 (display/render HAL) and 05 (adapters/RPC mechanics) cover the generic machinery; this chapter covers what is specifically _alignment_: the four adapters' output, the worker-side pileup/chain computation, the serialized per-read arrays that cross the worker boundary, coverage & SNP-coverage aggregation, base modifications (MM/ML), grouping/sorting/coloring tiers, the GPU pass composition, structural-variant arcs, and consensus calling.

Primary sources: `plugins/alignments/src/CLAUDE.md` (authoritative), `plugins/alignments/src/LinearAlignmentsDisplay/CLAUDE.md`, `plugins/alignments/src/RenderAlignmentDataRPC/CLAUDE.md`, and `agent-docs/reference/{BAM,CRAM}_STACK_INTEGRATION.md`, `DEEP_COVERAGE.md`, `MODIFICATION_TAGS.md`.

TL;DR: one RPC (`RenderAlignmentData`) serves both pileup and "chain" (paired/split-linked) modes, returning a wide DTO of **parallel typed arrays keyed by read index** (`WorkerPileupData`) — all positions absolute genomic uint32, 0-based half-open `[start, end)`. Position-aggregate layers (coverage band) are pre-packed into GPU instance buffers _in the worker_; row-instanced layers (pileup marks) carry `*Ys` arrays appended by main-thread layout (ADR-053: layout stays on the main thread so chains spanning regions share rows). Three invalidation tiers each have their own type: `WorkerPileupData` → `LaidOutPileupData` → `PileupDataResult`.

## 1. Adapters

All four alignment adapters live in `plugins/alignments/src/` and share `shared/BaseAlignmentsAdapter.ts` (sequence-subadapter wiring, from the assembly) and `shared/BaseSamAdapter.ts`. `sequenceAdapter` is auto-filled from the assembly — never configured by hand.

| Adapter            | File                         | Format / index                                | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------ | ---------------------------- | --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BamAdapter`       | `BamAdapter/BamAdapter.ts`   | BAM + BAI/CSI (`bamLocation`, `index`)        | Backed by `@gmod/bam`; records parsed by `BamSlightlyLazyFeature` (lazy, `recordClass` injection, ADR-049). Decompressed-byte budget `cacheBudget` (ADR-064), BGZF inflate worker pool, reference prefetch overlapped with the alignment fetch when the file carries no MD tag (`seqFetchSpan` clamps to the viewport, `withRegionRef` binds ref bases per query — records are SHARED across queries in a chunk LRU, so `record.ref = x` mutation is lint-banned `noRecordRefMutation`) |
| `CramAdapter`      | `CramAdapter/CramAdapter.ts` | CRAM + CRAI (`cramLocation`, `craiLocation`)  | `@gmod/cram`; `fetchSizeLimit` 5 MB warning budget. CIGAR is _rebuilt_ from CRAM read-features (`CramAdapter/packCigar.ts`, `readFeaturesToCIGAR.ts`); decoding requires the correct reference (mismatched ref silently decodes into mismatches, not an error). `CramSlightlyLazyFeature` mirrors the BAM one                                                                                                                                                                           |
| `SamAdapter`       | `SamAdapter/`                | plain SAM text, **unindexed**                 | Whole file loaded into memory; small files only (BLAT results, tests). Per-base mismatches computed against the assembly sequence adapter when no MD tag                                                                                                                                                                                                                                                                                                                                |
| `HtsgetBamAdapter` | `HtsgetBamAdapter/`          | htsget endpoint → BAM records via `@gmod/bam` | Slots `htsgetBase` (a _location_, not a string, so `serializeArguments` can attach OAuth/basic pre-auth) + `htsgetTrackId`                                                                                                                                                                                                                                                                                                                                                              |

Filtering (flags, read name, tag filters, read categories) is applied in the adapter's `getFeatures` loop — deliberately _not_ pushed down to `@gmod/bam` (upstream ADR 0005): the loop already visits every record.

Hot-path rules (from `plugins/alignments/src/CLAUDE.md`, verified against source): per-read extraction (`shared/extractFeatureArrays.ts`) calls `feature.get(...)` per read; `seq` and full tag decoding happen only in `toJSON()`; tag reads go through `getTag`/`getTagAlt` (single pass, duck-typed in `modifications-utils`), never `get('tags')` (decodes and memoizes every tag into a shared LRU); the `mismatches` getter allocates, so the render path uses `forEachMismatch`. Measured cost split (HG002-like fixtures): fetch (BGZF inflate) 54–89% of a query, per-read extraction 11–37%, per-read array builders ~0–9%.

## 2. The worker→main serialized data model

### 2.1 RPC surface

`RenderAlignmentDataRPC/` registers four RPC methods (`RpcMethodTypeWithFiltersAndRenameRegions`, so `renameRegionsIfNeeded` rewrites `regions[]` to adapter refNames before the worker sees them):

- `RenderAlignmentData` — the main fetch. Args (`RenderAlignmentDataRPC/types.ts` `RenderAlignmentDataArgs`): `adapterConfig`, `sequenceAdapter`, `regions`, `filterBy`, `colorBy`, `sortTag` (tag name only — moving the sort anchor does NOT refetch, layout re-runs on the main thread), `showSoftClipping`, `showCoverage`, `groupBy`, `lodMode` (`'fine'|'coarse'`, only synteny PIF adapters tier), `linkedReads` (`'off'|'normal'` — the pileup/chain branch), `byteLimit`, `perBaseBinBp` (sub-pixel bin stride for per-base color modes; carried via `regionFetchKey`, not `rpcProps`, so a bin flip refetches only visible regions).
- `GetPileupFeatureDetails` — right-click details; refetches a **single base** region (`start…start+1`) and matches the read id in the worker.
- `PileupGetGlobalValueForTag` — tag-value scan for the color-by-tag legend.
- `GetConsensusSequence` — §8.

### 2.2 `WorkerPileupData` — the transport payload (worker-built, per group)

`RenderAlignmentDataRPC/types.ts`. Everything is a function of the fetch alone; fields are parallel arrays indexed by read unless noted. All positions absolute genomic uint32, `[start, end)`.

Read-level:

| array                               | type                  | content                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------- | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `readPositions`                     | Uint32Array           | `[start, end]` pairs — the read's **true alignment span**, never clipped to the region (clipping is draw-time, `features/read/buildSegments.ts`)                                                                                                                                                                                          |
| `readFlags`                         | Uint16Array           | BAM flags (16-bit)                                                                                                                                                                                                                                                                                                                        |
| `readMapqs`                         | Uint8Array            | 0–255                                                                                                                                                                                                                                                                                                                                     |
| `readInsertSizes`                   | Float32Array          | **\|TLEN\|** — absolute value; 0 = unset (unpaired). Float because TLEN outgrows int16                                                                                                                                                                                                                                                    |
| `readPairOrientations`              | Uint8Array            | 0=unknown, 1=LR, 2=RL, 3=RR, 4=LL                                                                                                                                                                                                                                                                                                         |
| `readStrands`                       | Int8Array             | −1 reverse / 0 unknown / +1 forward. | `readNameBlock` + `readNameOffsets` | string + Uint32Array  | all QNAMEs as ONE string block; `readNameAt(data,i)` slices one out. | `readNextRefIds` + `nextRefNames`   | Int32Array + string[] | mate reference as a slot into a per-contig name table (one string per distinct contig, not per read)                                                                                                                                                                                                                                      |

| `readClipAtStart` (opt)             | Uint32Array           | 5' soft/hard clip length in read coords — read-order chain sort key                                                                                                                                                                                                                                                                       |

| `readTagValues` (opt)               | string[]              | only in tag _color_ mode; main thread bakes `readTagColors` from them (no color table crosses the worker — kills the discover→assign→refetch loop)                                                                                                                                                                                        |

Segments (per-exon instancing — reads are split at CIGAR `N` skips so introns render as separate blocks): `segmentPositions` (Uint32 `[start,end]` pairs), `segmentReadIndices`, `segmentEdgeFlags` (bit0 = first segment of read, bit1 = last), `numSegments`.

Gap / mismatch / interbase / softclip-base event arrays, all with a parent `*ReadIndices`:

- Gaps: `gapPositions` `[start,end]`, `gapTypes` (0 = deletion `GAP_DELETION`, 1 = skip `GAP_SKIP`, from `shaders/slang/gap.consts.generated.ts`), `gapFrequencies` (Uint8, 0–255 = 0–100% of depth at the start position).
- Mismatches: `mismatchPositions` (**ascending** — a contract consumers binary-search against), `mismatchBases` (ASCII code), `mismatchStrands` (±1), `mismatchQuals` (Phred 0–255; 255 = `QUAL_UNAVAILABLE`, 0 is a real score), `mismatchFrequencies`.
- Soft-clip bases (letters past the alignment end, drawn when `showSoftClipping`): `softclipBasePositions/Bases/ReadIndices`.
- Interbase (events between reference bases; stored sequentially as insertions, then softclips, then hardclips, sliced by three counts): `interbasePositions`, `interbaseLengths`, `interbaseTypes` (1=insertion, 2=softclip, 3=hardclip — `shared/types.ts` `INTERBASE_*`), `interbaseSequences` (string[]; empty for clips), `interbaseFrequencies`, `numInsertions/numSoftclips/numHardclips`.

Coverage aggregates (position-indexed, not per-read):

- `coverageDepths` Float32Array — per-bp depth, `depths[i]` covers `[coverageStartPos+i, +1)`; may extend beyond the region. Plus per-strand sweeps `coverageFwdDepths`/`coverageRevDepths` (coverage tooltip strand split; only computed when the band is drawn).
- `coverageStatsMins/Maxs/Sums/SumSqs` + `coverageStatsBinSize` — coarse partial stats (bin cap 65536) so main-thread autoscale reduce is O(bins) not O(bp) at whole-chromosome scale.
- **Pre-packed GPU instance buffers** (worker-built, uploaded verbatim): `coveragePackedBuffer` + `coverageBinSize`/`coverageGpuBinCount` (depth bars downsampled to a bin cap of 262144 so record count tracks pixels, not region width — whole-chromosome fetches would otherwise overflow the GPU device limit; `downsampleDenseMax` in `packages/alignments-core/src/coverageDownsampling.ts` is peak-preserving max per bin); `snpPackedBuffer` (§3); `interbasePackedBuffer` (stacked interbase histogram bars, fractions of `interbaseMaxCount` = the region's _peak read depth_, floored at 1 — not an event count); `indicatorPackedBuffer` (§3); `modCovPackedBuffer` (§4).

Modifications: `modificationPositions` (Uint32), `modificationColors` (packed ABGR u32; alpha byte encodes quadratic visual opacity), `modificationProbabilities` (raw 0–255, kept separate to avoid the lossy roundtrip in tooltips), `modificationReadIndices`, `modificationTypes`/`modificationTypeIndices`, `modificationNoMod` (1 = the "unmodified" bucket; `modType` stays the canonical code in both buckets). Per-base overlays: `perBaseQualPositions/Scores/ReadIndices` (only under `colorBy: perBaseQuality`) and `perBaseLetterPositions/Bases/ReadIndices` (under `perBaseLetter`).

Sashimi: `sashimiX1/X2` (Uint32, junction ends), `sashimiStrands` (Int8), `sashimiCounts` (Uint32 supporting reads), `sashimiMotifs` (Uint8 splice-site motif code: 0 unknown, 1–3 = GT-AG/GC-AG/AT-AC per strand, 7 = non-canonical — `features/sashimi/motif.ts`).

Chain metadata (chain mode only; absent as a group in pileup mode — `isChainData` narrows the whole set off `readChainIndices !== undefined`): `readChainIndices`, `chainAbsMinStarts/MaxEnds` (Uint32), `chainDistances` (TLEN or span), `chainNames` (QNAME, or a unique synthetic key for secondary alignments / nameless PAF blocks — `shared/chainGroupingKey.ts`), `chainFirstReadIndices`. Chain numbering is per worker call, so anything unioning chains across calls keys by `chainNames`, not index.

### 2.3 The three tiers (main thread)

- **Tier 1 → `WorkerPileupData`**: what the RPC returns (above). Set by settings in `rpcProps()` (tier-1 refetch).
- **Tier 2 → `LaidOutPileupData = WorkerPileupData & PileupLayoutArrays`**: main-thread layout (`cloneWithLayout` in `groupLayout.ts`) adds per-feature rows `readYs/gapYs/mismatchYs/softclipBaseYs/interbaseYs/modificationYs/perBaseQualYs/perBaseLetterYs` (Uint16), `maxY` (rows the group occupies, shared across regions laid out together), `clippedBy?: RowCapSource`, connecting-line arrays, chain overlap spans, linked-read line arrays, and two Flatbush R-trees (`chainFlatbush` over chain bounding boxes, `modFlatbush` over modification points) for hit testing. `withoutLayout` is the zero-row answer (empty region, collapsed lane) — a real layout, not a gap.
- **Tier 3 → `PileupDataResult`**: adds `readTagColors` (packed ABGR u32 per read, 0 = no color; baked by `overlayReadTagColors` from `readTagValues`) then `readColorCategories` (Uint8 RC_* index per read, baked by `overlayReadColorCategories` — which takes the tag-colored tier because the `noTagValue` bucket reads off `readTagColors`).

The type ladder is deliberate: the worker cannot ship a placeholder for a field whose real producer lives on another tier, and a pass that only reads fetched arrays (arcs, sashimi, coverage domain) can be fed any tier.

**Row-instanced vs position-aggregate.** Features carrying `*Ys` are packed on the **main thread** at upload (a read's row isn't known until all visible regions lay out together — ADR-053). Position-aggregate features (coverage band) are row-independent; the worker packs them once and the main thread uploads bytes verbatim. `regionMeta` is derived separately so an unchanged payload still refreshes metadata while skipping the pack.

### 2.4 Transfer and grouping envelope

`collectTransferables` detaches ArrayBuffers for zero-copy postMessage; the reply is `GroupedAlignmentsResult { groups: AlignmentGroup[], bytes? }` where `AlignmentGroup { key, label, data: WorkerPileupData, mergedKeys? }`. Ungrouped fetches return one group with `key: ''` — one uniform code path.

## 3. Coverage & SNP coverage (all worker-side)

`shared/runCoveragePipeline.ts` fixes the step order — compute → frequencies → SNP → interbase → mod → mod-tooltip → sashimi → pack — shared by both pileup and chain executors so it cannot drift.

1. **Depth sweep** `computeCoverage` (`packages/alignments-core/src/coverageCompute.ts`): per-bp Float32 depth over `[regionStart, regionEnd)`, plus optional per-strand sweeps. A single-read depth of 1 is the floor for log scales (`coverageDepthDomain` floors the log domain at 1 — depth counts whole reads, unlike a wiggle track).
2. **Frequencies** `computeFrequenciesAndThresholds` (`shared/computeFrequenciesAndThresholds.ts`): for every mismatch/interbase event/gap, `count_of_that_base_at_that_position / depth_at_that_position`, quantized to Uint8 (0–255). Counts use a flat per-bp lane array (A/C/G/T/N lanes + a `Map` fallback for IUPAC/rare codes) sized to the events' span, not the window. Computed **before** the `showCoverage` gate — the pileup's low-frequency fade must be identical with the band off. Positions whose frequency is below the depth-dependent threshold are **zeroed in the worker**: `featureFrequencyThreshold(depth)` (`LinearAlignmentsDisplay/constants.ts`) ramps 0.8 below 10× → 0.3 at ≥30× (a 50% het first clears it at 22×). Gate `showLowFreqMismatches` (repaint-tier) flips the polarity: full opacity instead of fade.
3. **SNP coverage** `computeSNPCoverage` (`packages/alignments-core/src/snpCoverage.ts`): walks the ascending mismatch arrays in runs per position, counts lanes (1=A 2=C 3=G 4=T 5=N/other-grey), and emits stacked segments as **fractions of that position's depth bar**: 20-byte stride records `{position: u32, yOffset: f32, segHeight: f32, colorType: f32, relDepth: f32}` where `relDepth = depthAtPos / regionMaxDepth` rescales at draw time. Output is position order then lane order. `coverageSnpMinFrequency` (config slot, default 0; IGV uses 0.2) is a _draw-time_ floor against `segHeight` in both backends — repaint, not refetch.
4. **Interbase coverage + indicators**: stacked insertion/softclip/hardclip histogram bars hanging from the coverage band top; indicator triangles where interbase events are a significant fraction of local depth — the depth basis is the **deeper of the two flanking bins** (`interbaseDepthAt`, interbase sits at a base boundary). Indicator rules: absolute depth floor 8 (`MINIMUM_INDICATOR_READ_DEPTH`) then a flat 0.3 fraction (`INDICATOR_THRESHOLD`).
5. **Sashimi**: `computeSashimiJunctions` groups skip gaps into junctions (`junctionKey` includes refName); splice motifs read from the reference sequence, fetched only when the region carries a skip gap.
6. **Packing** `packCoverageAreaForGpu` → the five `ArrayBuffer`s of §2.2. The buffer IS the representation (decode side: `snpSegments.ts`, `modCovSegments.ts`, `readInterbaseSegments.ts`, field offsets are Slang codegen).

Three _independent_ frequency thresholds (measured on HG002 300x, `agent-docs/reference/DEEP_COVERAGE.md`): the pileup's depth-ramped `featureFrequencyThreshold` (worker, zeroed bytes), the band's flat user-set `coverageSnpMinFrequency` (draw time, default 0), and the indicator's depth-floor-8-then-0.3. They are not calibrated alike and a 50% het is invisible in the pileup under 22× while the band still colors it.

## 4. Downsampling, caps, and surfacing

There is **no read subsampling** (no samtools-style `-s` cap). What limits the render:

- **Row cap** `maxHeight` (config slot, default 6000 px): reads beyond it are not stacked — they collapse onto the bottom row; coverage still reflects true depth. Four cap sources travel with the layout as `RowCap {rows, source}` (`RowCapSource = 'ceiling' | 'budget' | 'override' | 'collapse' | 'uncapped'`): `'ceiling'` (display-wide maxHeight; draws an inert `PileupTruncationRule`), `'budget'` (lane's slice of the fit-to-viewport split; expandable via chip), `'override'` (user cap, fires nothing), `'collapse'` (`collapseGroupRows` — one row per group, overlap depth carried by the tint layer). Only `'budget'` and `'collapse'` can be expanded out of.
- **Byte gate**: `estimatedBytesForRegions` (BAM: `chunksLikelyRead` forecast) vs `fetchSizeLimit` (5 MB default) → a banner with Force Load, plus `byteLimit` in RPC args.
- **GPU bin caps**: depth bars downsampled to ≤262144 bins (peak-preserving max), stats sidecar ≤65536 bins — the only "downsampling" (`packages/alignments-core/src/coverageDownsampling.ts`). Both return the input verbatim with `binSize: 1` when it already fits, so zoomed-in output is byte-identical to per-bp.
- **Group overflow**: `MAX_GROUPS` per worker call (each group allocates region-width depth arrays + its own GPU coverage buffer); tail groups merge into one overflow lane whose label counts _this call's_ merges only — the drawn lane's union is sized by `orderedGroups` on the main thread.
- `showCoverage: false` (the `LGVSyntenyDisplay` default) makes the worker skip every band computation and return an empty depth array — the per-bp buffer alone is regionWidth×8 bytes and overflows the device limit at chromosome scale; the pileup frequency fade is unaffected.

## 5. Base modifications (MM/ML)

`packages/modifications-utils` parses the SAM MM/ML tags; the reference semantics are htslib's `sam_mods.c` (`agent-docs/reference/MODIFICATION_TAGS.md`, checked against htslib 1.23.1).

- **Vocabulary**: a _combined code_ (`C+mh`) = several types on the same canonical base at the same positions — one delta list, ML values interleaved per position. _Several MM groups_ (`C+m,…;A+a,…`) = different bases, necessarily different positions. Common in the wild (dorado): several groups on the same base with separate delta lists (`A+a.;C+h?;C+m?`) — two sequence walks after same-base merging.
- `getModPositions` (`getModPositions.ts`): walks the read sequence once per distinct (base, strand, delta-list) group — types of one group share a walk; two groups with the same base/strand/deltas share one (decided by comparing the delta text at parse time; 1.27× on parse). Forward reads find each call with `indexOf` jumps; reverse reads step with `charCodeAt` (branch on strand — `lastIndexOf` measured 0.786×). **Overrun rule**: when MM asks for more of a base than the read has, every unplaceable call clamps to `seqLength − 1` (forward) / 0 (reverse), keeping positions valid indices and ascending for the CIGAR walk. htslib validates `MN` against read length and reports runs-over; this repo does neither.
- `forEachMaxProbMod` packs mod index into the high byte of a Uint16Array (256-type ceiling, same as htslib's `MAX_BASE_MOD`); entries sharing a positions array (by _identity_, like htslib's pointer compare) share the CIGAR walk.
- **Methylation / bisulfite**: `getMethBins` (fill-unmarked cytosine walk, C/T context via `cytosineContext`: CpG default, CHG/CHH for plants), `getModProbabilities`, `detectSimplexModifications` (single-modification-simplex reads for the mod-coverage denominator).
- **Extraction to rendering** (`plugins/alignments/src/features/modification/extract.ts`, `shared/webglRpcTypes.ts` `ModificationEntry {readIndex, position, base, modType, strand, color (packed ABGR), prob (0–1), noMod?}`): one entry per called modification position per read. The "no-mod" bucket carries the same canonical `modType` with `noMod: true` and prob = confidence the base is *un*modified (IGV's `NONE_<base>`). Aggregates per position feed the mod tooltip index (`shared/modTooltipIndex.ts`, flat transferable arrays `modTooltipPositions/Offsets/Counts/Fwd/Rev/ProbTotals/Colors/LabelIds` + `modTooltipLabels`) and the mod-coverage band (`features/modCoverage/compute.ts`: stacked per-position colored bars, denominator from a read-base pileup `modBaseCounts` — IGV-style, no reference needed; bisulfite mode divides by `extractBisulfite` call counts instead).
- **Visibility config** (`shared/types.ts` `ModificationColorBy`): `shownModifications` allow-list wins over the legacy `hiddenModifications` deny-list; absent = every detected type; empty list = draw nothing (a real state). `twoColor` paints the unmodified side blue; `fillUnmarked` subsumes the old standalone "methylation" scheme; `threshold` default 10% (`DEFAULT_MODIFICATION_THRESHOLD`). `isModificationTypeVisible` is the single predicate shared by worker extract filter, legend, and menu.
- Bisulfite (`colorBy: 'bisulfite'`) reuses the modifications shader path with C→T vs reference calls.

## 6. Sorting, grouping, coloring — what runs where

### Worker (tier-1 refetch inputs, in `rpcProps()`)

- **Filters** `filterBy` (`shared/types.ts` `FilterBy`): `flagExclude` (default 1540 = unmapped 0x4 + vendor-fail 0x200 + duplicate 0x400), `flagInclude`, `readName`, AND-ed `tagFilters[]`, and four _read categories_ (`'only'|'exclude'`, absent = unfiltered): `spliced` (CIGAR has N; decided per record in the adapter), `properPairs` (flag 0x2 **and** normal FR orientation), `singletons` (mate + supplementaries absent from window), `split` (SA tag present — read off the tag, not off what this window fetched). The chain-level three are applied in the worker (`filterChainFeatures`) because they need the whole chain. Unknown category strings mean UNFILTERED, said once (`categoryFilters`), because a frozen slot carries no MST validation.
- **ColorBy**: only `workerColorBy(colorBy)` — the part the worker reads — is in `rpcProps`, so shader-decided schemes (strand, mapq, insert size, pair orientation) repaint from existing arrays without refetching. All 13 schemes (`ColorSchemeType`) map to 9 shader dispatch paths (`ShaderScheme`); per-base modes (`perBaseQuality`, `perBaseLetter`) instead ship per-base overlay arrays (§2.2) and tag/mateRefName bake CPU colors into `readTagColors` via the `tag` shader path.
- **Tag sort values** (`sortTag` name only) and **group partitioning**: `groupBy` (`GroupByType = strand | firstOfPairStrand | tag | pairOrientation | splitRead | mapq | mateAssembly`) makes the worker return one `WorkerPileupData` per group. In chain mode only fragment-level dimensions survive (`groupByForMode` degrades a per-read dimension rather than splitting a chain; `partitionChains` assigns chains as units). `mapq` groups bin by confidence (bimodal at aligner ceiling), not decades. Chain grouping key: `chainGroupingKey` gives secondary alignments unique synthetic keys and nameless reads their own chain.

### Main thread (tiers 2–5, auto-wired by MobX)

- **Layout/sort**: `RenderAlignmentDataRPC/sortLayout.ts` + `LinearAlignmentsDisplay/{groupLayout,sectionLayout,lanes}.ts`. `sortedBy` (`SortedBy {type, pos, refName, assemblyName, tag?}`) applies **only when every laid-out region is on `sortedBy.refName`** (`sortForRegions` gate — a sort set at chr1:1000 must not reorder chr2; refName canonicalized, unresolvable alias = unsorted). `partitionBySort` distinguishes interbase marks: a right-edge clip is recorded at the read's _exclusive end_, so `end > sortPos` would wrongly sink clipped reads. Non-tag sort changes are pure relayout. Layout-order flags: `largeFeaturesFirst`, `splicedReadsFirst` (both ignored under a position sort; neither reaches chain layout).
- **Recolor**: `readTagColors` then `readColorCategories` bakes (tier 3). Chain frames: `readChainHasSupp` is a bitfield — `CHAIN_SUPP_PRESENT (1<<0)`, `CHAIN_FRAME_REV (1<<1)` (chain-level sign), `CHAIN_SPLIT_INVERSION (1<<2)`, `CHAIN_SPLIT_DELETION (1<<3)` (per-mate split kind) — and `CHAIN_FRAME_REV` is **overwritten twice on the main thread** (`chainSuppAcrossRegions.ts` reconciles a molecule across regions; `chainStrandConsensus.ts` frames every chain against the orientation the chains on screen agree on, purity-normalized votes, frozen for chains seen at one locus; the slot formerly named `flipStrandLongReadChains` keeps its name for session compatibility). The worker's primary-strand frame is arbitrary on foldbacks — main-thread consensus reached 100% vs 58/52/61% for alternatives.
- **Repaint** (tier 4, `renderState`): all show flags, resolved coverage domain/scale/symlog constant, sections geometry, selection. Per-mousemove state (hover) is a React overlay, never tier 4.
- Arc-only settings (`arcColorByType`, `drawInter`, `drawLongRange`) are _not_ in `rpcProps` — the arcs feed is a separate derived structure rebuilt on those reads.

## 7. Rendering composition

### Pass registry

`LinearAlignmentsDisplay/renderers/pileupLayers.ts` `PILEUP_LAYERS` — the pileup-band layer list in z-order, mapped exhaustively to GPU shader passes (`GPU_PILEUP_PASS` in `renderers/GpuAlignmentsRenderer.ts`) and Canvas2D draw fns (adding a layer is a compile error in both): `connLine` (chain mode), `linkedReadLine`, `read`, `overlap` (same-row chain overlap tint), `mod`, `perBaseQual`, `skip` (always — the intron centerline is _structure_ saying per-exon blocks are one read), `deletion`, `mismatch`, `insertion` (all gated on `showMismatches`), `clip` (always; soft AND hard clips from one shader — `features/clip/` owns both emitters), `softclipBases`, `perBaseLetter`. The coverage band has its own list `COVERAGE_LAYERS` (`renderers/coverageLayers.ts`) because its marks are position-aggregate. The arc band is four GPU passes against one `drawArcs` (`ARC_PASSES`), plus a main-thread SVG overlay (`CrossRegionArcsOverlay`) for arcs no per-region GPU buffer can draw — a GPU pass never joins two displayed regions. The geometry of converted passes is declared once in `features/mark.ts` (`PileupMark`) and the packer/painter/hit-test derive from it.

Pass directories follow one canonical file set (`plugins/alignments/src/CLAUDE.md`): `extract.ts` (worker, per-read extraction), `buildArrays.ts` (worker), `packGpu.ts` (GPU instances), `drawCanvas.ts` (Canvas2D), `hitTest.ts`, `types.ts`. `sashimi/` and `derivativePaths/` are not passes — they compute geometry for React SVG overlays.

### Hit testing

`HIT_GATES` (hit-test gate parity test, exhaustive over `PileupLayerId`) forces every draw gate to state a matching hit story; zoom is a second axis (`performHitTest` drops per-base tests above `SNP_HIT_MAX_BP_PER_PX`). `passesFrequencyGate` keeps below-threshold marks visible-but-inert between ~1 and ~3 bp/px. Neither index-backed test may take `hits[0]` — Flatbush returns Hilbert order; modifications pick by distance, chains by highest index ("last drawn wins"). The arc band is hit-tested first and short-circuits `performHitTest`.

### Upload flow

Main thread: layout tiers 2–3 run in `laidOutPileupMap`; `attachRenderingBackend`'s upload autorun packs row-instanced passes into per-region GPU instance buffers (`uploadPass` per `GPU_PILEUP_PASS`/`GPU_COVERAGE_PASS` entry) and uploads the worker-packed coverage buffers verbatim; the render autorun draws passes in z-order per region. Shaders are `.slang` (`plugins/alignments/src/shaders/slang/`), compiled by `pnpm gen:shaders` into `*.generated.ts`; CPU layout code imports generated twins of shader geometry expressions (ADR-051).

## 8. Consensus, SV arcs, splice junctions

- **Consensus** (`RenderAlignmentDataRPC/GetConsensusSequence.ts` + `packages/alignments-core/src/consensus/`): a worker RPC porting samtools' `bam_consensus.c` "simple" path (`calculate_consensus_simple` weight tables reproduced exactly, cross-checked against samtools 1.23.1 over volvox). Args: `minDepth`, `callFract` (default 0.75, samtools `--call-fract`), `hetFract` (opt-in IUPAC ambiguity, ratio-to-winner not capped at one runner-up — a real 3-way split reports as such), `includeInsertions`, `filterBy`. Output `{consensus: string, variants: ConsensusVariant[]}` where `ConsensusVariant {pos (0-based), ref, alt, depth, af, type: 'snv'|'ins'|'del'}` is a consensus-vs-reference diff (deliberately _not_ genotype-likelihood calling); deletion AF is the weighted winning-call fraction, insertion AF the supporting-read fraction. Requires a sequence adapter.
- **Read-connection arcs / SV** (in-plugin, `features/arcs/`, `shared/readGroupConnections.ts`): mates and supplementary segments chained by `readKeys`+SA; arcs colored by `arcColorByType` (default `insertSizeAndOrientation`), classified short/normal/long against `InsertSizeBand {upper, lower}` = median ± 3·1.4826·MAD over proper pairs, **floored by `widenBandToEventScale` to 2×/0.5× the typical fragment** (the raw band painted 1% of a tight 300× library as "long insert" — its own tail). Interchromosomal ticks require `minInterchromSupport` (default 2) reads **clustered over a window of one fragment length on both sides** (`clusteredInterchromSupport`) — a mate straddles a breakpoint, so exact-coordinate counting deletes real translocations along with the 98% of single-read mismapping noise. Concordant-pair arcs hide behind `drawProperPairArcs` (a two-condition rule: proper flag AND baseline slot). "Derivative allele" reconstruction (`features/derivativePaths/`, `ReadVsRefDialog/`) chains SA segments into contig-level paths.
- **sv-core** (`packages/sv-core/src/`): breakpoint split-view plumbing — `walkBreakendChain` (multi-hop BND chains), `findJunctionsNear`, `launchBreakpointSplitView`/`navToMultiLevelBreak`; UI-facing, thin.
- **plugins/arc** (`LinearArcDisplay`, `LinearPairedArcDisplay`): _not_ alignment-specific — draws any FeatureTrack's features as one arc each (bezier `arcs` or `semicircles`), styled by per-feature JEXL slots (`color`, `thickness`, `label`, `arcHeight`); fetched through its own `ArcGetFeatures` RPC with the byte gate. The alignment read-connection arcs live entirely in the alignments plugin.
- **Sashimi** (`features/sashimi/`): junctions from skip gaps; `minSashimiScore` default 2; motif filter `hideNonCanonicalJunctions` (needs the sequence adapter); band side ('up'/'down'/'auto') decided once in genomic bp per group (`sashimiDownKeysByGroup`).
- **saveTrackFormats/sam.ts**: re-serializes fetched features to SAM text (`@HD`/`@SQ` from the assembly, Phred `+33` quals) for "Save track data".

## 9. Viewport-state field inventory (`LinearAlignmentsDisplay`)

The display model is MST (`LinearAlignmentsDisplay/model.ts`, ~4000 lines of thin getters over sibling modules; state census: 46 config slots, 2 properties, 13 volatiles). Slot inventory that transfers to a Rust viewport struct:

**Data-shape slots (tier-1 refetch via `rpcProps()`)**: `filterBy` (frozen), `colorBy` (frozen, promotable sentinel `{type:'normal'}`), `groupBy` (frozen), `sortedBy` (frozen; `sortTag` derived — tag name only), `showSoftClipping` (worker gates per-base extraction on it), `showCoverage` (worker skips the band), `lodMode` (subclass-set), `linkedReads` (`'off'|'normal'` — selects the RPC branch).

**Repaint slots (tier 4)**: `showMismatches`, `showInterbaseIndicators`, `showBezierConnections`, `showOutline` (null=auto), `collapseGroupRows`, `largeFeaturesFirst`, `splicedReadsFirst`, `mismatchAlpha`, `showLowFreqMismatches`, `showLegend`, `flipStrandLongReadChains` (legacy name), `colorSupplementaryChains`, `drawInter`, `drawProperPairArcs`, `minInterchromSupport` (2), `arcColorByType`, `readConnections` (`'off'|'arc'|'cloud'`), `readConnectionsDown`, `readConnectionsHeight` (35), `readConnectionsLineWidth` (1), `showSashimiArcs`, `sashimiArcsMode`, `minSashimiScore` (2), `sashimiArcsHeight` (40), `showSashimiLabels`, `hideNonCanonicalJunctions`, coverage axis: `autoscale` (`local|localsd`), `minScore`/`maxScore`, `scaleType` (`linear|log|symlog`), `symlogConstant` (1 → exactly log(depth+1)), `numStdDev` (3), `coverageSnpMinFrequency` (0).

Key derived getters: `colorBy`/`filterBy`/`groupBy`/`sortedBy` (each normalized/canonicalized at exactly one read site), `featureFrequencyThreshold`-aware `filterMismatchesByFrequency`, `isChainMode` (`linkedReads === 'normal'`), per-lane `RowCap`/`clippedBy`, `renderSections` (lane + band geometry; a `renderSections` entry carries every per-lane answer), six distinct grouping questions (`prefersOffset`, `canCollapseGroupRows`, `canSizeGroupHeights`, `canSortReads` from settings alone; `showsGroupLabels`, `isGrouped` from fetched lanes).

## Mab notes

- **The parallel-typed-array DTO is the core transferable design.** One read index fans out into ~25 columnar arrays (positions, flags, mapq, strand, TLEN, orientation, identity, names-as-a-block, mate refs, SA tags, per-event arrays with parent indices). It is clone-cheap, cache-friendly, and GPU-uploadable directly. A Rust design should make this the wire format (e.g. Arrow/flatbuffers) and treat the per-read "feature object" as an adapter-local view, never the transport.
- **Copy identity, not strings.** Read identity is a numeric record id (Float64 headroom — BAM virtual offsets overflow u32) plus a prefix; names ship as one string block + offsets; mate refs as a slot table. A Rust reader should keep QNAMEs as byte ranges into the BAM block until something actually displays them.
- **Absolute 0-based half-open u32 coordinates everywhere; no region-relative arithmetic crosses the fetch boundary.** Clipping to the viewport is purely draw-time. Keep this invariant even if it costs larger arrays — it is what makes per-region caching composable.
- **Compute frequencies in the producer, not the consumer.** Mismatch/interbase/gap frequency bytes (and the depth-ramped noise threshold) are zeroed in the worker so every renderer, hit-test, and export agrees and the result is cacheable per fetch. Draw-time-only thresholds (band allele floor) stay as repaint parameters.
- **Separate "what a fetch produces" from "what layout adds" from "what recoloring adds"** as distinct structs/tiers; each user setting then declares which tier it invalidates (refetch / relayout / rebake / repaint), and the compiler can enforce that a worker payload never contains a field only layout can know.
- **Pre-pack GPU instance buffers where rows don't matter** (coverage band segments, packed as fixed-stride fraction records: yOffset/segHeight relative to the position's own bar, relDepth to the region max) — it makes scale changes (log/linear, autoscale) pure uniforms instead of repacks. Do the same trick for any per-position aggregate.
- **Two caps, two semantics**: a layout row cap (reads collapse; coverage stays truthful; record _which_ cap clipped so the UI knows whether expanding is possible) and peak-preserving bin downsampling of depth data for GPU upload. No read subsampling — deep coverage is handled by capping rows and binning aggregates, which keeps coverage histograms honest.
- **Strand discipline**: convert SAM flags to strand exactly once, in the record class, and carry flagless records (PAF/synteny) through the same pipeline with strand=0 — JBrowse lint-enforces this after repeated bugs.
- **Port the samtools consensus "simple" tables verbatim** (`SEQI2A…` weight tables, callFract 0.75, ratio-based IUPAC folding) — it is small, golden-tested, and gives a free QC feature.
- **Threshold calibration warns against fraction-of-sample cuts** at high depth (a cut calibrated as a fraction flags a fixed fraction however deep the pileup): use absolute-depth floors or scale-free bands (2×/0.5× median fragment) and window-based support counting (one fragment length) for breakpoint evidence.
- **MM/ML parsing**: per-group sequence walks with same-base delta-list merging, `indexOf` jumps forward / stepping reverse, clamp-to-last-base overrun handling, identity-shared position arrays. The materialized positions list is what enables random-access tooltips and one-CIGAR-walk rendering — worth the memory over a streaming design.
- Ambiguity worth deciding deliberately in Mab: JBrowse ships _three_ unaligned frequency thresholds (pileup ramp, band floor, indicator floor) that a user can set to disagree; a fresh design could unify them behind one significance predicate — but note the low-depth case where the band's floor of 0 is intentionally the only place a 50% het under 22× is visible.
