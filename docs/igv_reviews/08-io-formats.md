# 08 — I/O Formats: Complete Catalog

TL;DR: IGV routes every resource through `org.igv.track.TrackLoader.load(ResourceLocator, Genome)`, which dispatches on a format string (from extension, `.genome`/`.xml` session metadata, or content sniffing in `org.igv.track.FileFormatUtils.determineFormat`). Text feature formats go through htsjdk-tribble codecs selected by `org.igv.feature.tribble.CodecFactory`; binary formats (BAM/CRAM, BigWig/BigBed, TDF/IBF, 2bit, FASTA) have dedicated readers. Nearly all "features" are 0-based half-open (`start` inclusive, `end` exclusive) internally, and IGV normalizes every parser to that convention at read time.

Cross-references: feature model → `02-feature-model.md`; alignment internals → `04-alignment-model.md`; genome/sequence/2bit model → `01-genome-model.md`; TDF storage details → `05-storage-query.md` (this chapter covers format framing only).

## 1. Master format table

Internal convention everywhere is **0-based, start-inclusive / end-exclusive** unless noted. "Queryable" = supports random-access queries (region fetch without full-file scan).

## 2. Format auto-detection

Two layers, in `org.igv.track.TrackLoader.load()`:

1. **Format string.** `ResourceLocator.getFormat()` — set from file extension (in `ResourceLocator`), from session XML/JSON metadata, or from user choice in load dialogs. `TrackLoader` then dispatches on this string with a long `if/else` chain (see source lines ~141–235): exact matches (`seg`, `wig`, `bw`, `tdf`, `bedpe`…), suffix matches (`GWASParser.isGWASFile` catches anything ending `logistic`/`linear`/`assoc`/`qassoc`/`gwas`), and `CodecFactory.hasCodec()` as the tribble fallback.
2. **Content sniffing.** `org.igv.track.FileFormatUtils.determineFormat(path)` reads the first 1000 bytes (transparently gunzipping), then:
   - magic numbers: `BAM\1`→bam, `CRAM`→cram, BigWig/BigBed magic (0x888FFC26 / 0x8789F2EB), `"TDF"`/`"IBF"`→tdf;
   - header lines: `##fileformat=VCF…`→vcf, `##gff-version 3`→gff3, generic `##fileformat=X`→lowercase X;
   - first 100 lines: UCSC `track` lines — `format=` or `type=` attribute (restricted to `knownBedFormats = {interact, broadpeak, narrowpeak, gappedpeak, regionpeak, bedgraph}`) wins; `fixedStep`/`variableStep`→wig;
   - tab-separated UTF-8 with ≥2 tabs → `sampleinfo`.
     Generic `.bed` files always go through sniffing to resolve subtypes. Unrecognized files: content-based retry (via `determineFormat`), then cyto-band heuristic, else error. Loading a `.tbi`/`.bai`/`.sai`/`.csi` directly produces an explanatory error.

Special sniffing: VCF version (3.x vs 4.x) from the `##fileformat` line in `CodecFactory.getVCFCodec()`; MUT vs MAF (`MUTCodec.isMutationAnnotationFile` checks headers, and is tried before `.maf`); `WiggleParser.isWiggle` for extension-less wig files.

## 4. Coordinate-convention summary

| Source convention                                        | Conversion point                                                                          |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| BED family, BigWig/BigBed, 2bit, MAF, BAM/CRAM internals | already 0-based half-open — no conversion                                                 |
| GFF/GTF/GVF col 4                                        | `start = parse - 1` (`GFFCodec`)                                                          |
| VCF POS                                                  | `start = POS - 1` (htsjdk `VariantContext` already 0-based; wrapper maps to `VCFVariant`) |
| MUT/MAF(mut) position                                    | 1-based col → 0-based in `MUTCodec`                                                       |
| seg / GWAS BP / igv cn files                             | 1-based start col → 0-based in respective parsers                                         |
| interval_list                                            | 1-based inclusive (Picard) → 0-based                                                      |
| wig                                                      | configurable `startBase` (default 1 = 1-based); fixedStep start is 1-based                |
| FASTA `.fai` byte offsets                                | 1-based in the index file, converted at read                                              |

End columns are stored internally as **exclusive** ends everywhere; UCSC gene tables' `txEnd`/`cdsEnd` are already exclusive in UCSC convention.

## Mab notes

- **Normalize at the edge.** IGV's pattern — every parser converts to one internal convention (0-based half-open) — is the single most transferable idea here. In Rust, make the coordinate system a type-level fact (e.g. `Position<U32Zero>` vs `Position<U32One>`) and force conversions in parser code, not in rendering.
- **Format string + sniffing two-pass dispatch** is simple and effective: extension sets a provisional format, magic-byte/header sniffing refines it. A Rust `enum FileFormat` plus a small `detect(bytes)` function mirrors this cleanly; the sniffing table above is a ready-made test fixture list.
- **Codec-as-trait** (`CodecFactory` returning one codec interface) maps naturally to a Rust trait `FeatureCodec { type Feature; fn parse_line(...) }` — one object per format, selected by an enum, is how IGV keeps `TrackLoader` ignorant of format details.
- **Tribble indexing** (per-chromosome + binning `.idx`) and tabix/BAI are htsjdk artifacts; for Mab consider generating a single internal index format at import time rather than supporting five index dialects. What matters is the contract: `query(chr, start, end) -> iterator` with block-based random access.
- **Binary formats are worth the effort:** BigWig/BigBed (zoom levels + B+/R-trees), 2bit, and BAM/CRAM have Rust crates (`bigtools`, `noodles-*`) that cover essentially the same ground as `org.igv.ucsc.bb`, `org.igv.ucsc.twobit`, and the htsjdk alignment path — prefer crates over reimplementing.
- **TDF/IBF is IGV-specific** and largely redundant if Mab can stream BigWig directly; treat it as reference for the "precomputed multi-resolution tile" design, not as a format to adopt.
- **Writers are few on purpose.** Start Mab with a reader-heavy surface; the only writers worth early investment are SVG snapshots (use `svg` crate with a `Renderer` abstraction so the same paint code draws to both raster and vector), session JSON, and region-list export.
- **Formats with no random access** (seg, GWAS, bedpe, gct, interact) are simply loaded whole — a fine default for small tables; document which formats a user can expect to be memory-resident.
- Ambiguities worth verifying before coding: exact wig `startBase` semantics per subtype (`WiggleParser` default is 1-based, but bedGraph paths behave 0-based); UCSC gene-table end-convention handling; whether `.hic` files loaded through the bedpe path use full `.hic` support or only an interaction subset.
